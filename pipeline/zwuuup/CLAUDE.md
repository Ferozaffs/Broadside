# Pirate Game – 2D Art Pipeline (handover)

A local image-generation pipeline on the user's ComfyUI for Broadside's art: character dialogue portraits first, then
idle animations and 3D models (see `docs/`). Read this before generating anything. The method across all of
Broadside's content is in `docs/CONTENT_PIPELINE.md` in the Broadside repo.

## 1. Art direction

- **Asset type:** dialogue-screen character portraits: the character stands at one side of the screen, a dialogue
  box beside them, and the screen edge cuts the body at about mid-thigh ("2/3 body").
- **Deliverable per character:** transparent-background PNG (`*_alpha.png`) plus the original on dark grey.
- **Style: `amadmir`** (the user's decision): comic-book ink linework, fine hatching, muted desaturated colours,
  painted shading. Always pass `--style amadmir`.
- **Consistency rule:** the STYLE + FRAMING text is fixed. Change only the CHARACTER text between characters, or the
  cast won't match. A style change is agreed with the user once, made in `tools/make_workflow.py`, then frozen.

## 2. Hard rules

- ComfyUI belongs to the **user**, on **port 8188** (they also use it for music and video).
  1. **Never start a second ComfyUI server** (two exhaust the GPU and Flux slows from ~3 s to minutes a step).
  2. **Only queue when the queue is empty** (`tools/generate.py` and `comfy_guard.py` wait for this). Never cancel
     or interrupt the user's jobs or kill their processes. If the user cancels one of yours, stop and ask.
  3. New model downloads go on the models drive (`extra_model_paths.yaml`), not the system drive.
  4. A model that needs a site login: the user downloads it in their browser. Never ask for or handle their
     account keys.

## 4. Workflows

Generated by `tools/make_workflow.py`, the **single source of truth**: edit it, then
`python -I tools/make_workflow.py "<ComfyUI>/user/default/workflows" tools/api` rewrites the UI workflows and the API
JSONs that `generate.py` uses.

| Workflow | Pipeline | Output size | Time/image |
|---|---|---|---|
| `Amadmir-Flux-Character-Portrait` | Flux Q6_K + Amadmir LoRA 1.0, guidance 3.5, CFG 1, 25 steps euler/simple → BiRefNet alpha | 896×1152 | ~85–105 s |
| `Amadmir-Flux-Game-Assets` | prop/item version, no alpha output | 1024×1024 | — |

API node ids: `20` = CHARACTER text, `21` = STYLE + FRAMING text, the KSampler holds the seed.

## 5. How to generate

```
python -I tools/generate.py --style amadmir --name captain_redbeard --count 4 --character "<sentences>"
python -I tools/generate.py --style amadmir --name captain_redbeard --seeds 424242 --character "<sentences>"
```
- Files go to `assets/characters/<name>/<name>_<style>_s<seed>.png` and `..._alpha.png`.
- Every run appends to `generation_log.jsonl` (time, style, character text, seed, files): the shared record between
  you, the user and any other agent; **never rewrite it, only append**.
- Explore with `--count 4`, show the user, then lock the chosen seed and iterate on wording with `--seeds <seed>`.
- Check the alpha version for clipped thin weapons and hair.

**CHARACTER text:** one to three natural sentences starting with "The character is ...":
`The character is a weathered pirate captain with a braided red beard and a scar across his cheek, wearing a navy blue
long coat with tarnished gold buttons and a black tricorn hat. He rests one hand on a cutlass at his hip and smirks.`

## 6. Findings

- The style is very stable across characters, prompt adherence is good (props and details come through).
- **Framing:** at 832×1216 it drew full body for most characters even when told to crop at mid-thigh (the LoRA's
  full-body bias). At **896×1152** about 3 in 5 come out framed at the thigh; see §8.
- BiRefNet cut-outs are usually clean but **can delete props held away from the body** (a lantern vanished): always
  compare `_alpha.png` with the original.
- Named props sometimes change form (a sword became a claw-like blade): reroll or describe them more concretely.

## 7. Look B (the user's choice)

The default STYLE text is the gritty one: heavy black ink, scratchy cross-hatching, dry-brush texture, deep shadows,
high contrast, worn surfaces, muted cold palette, smoky textured background, intense stare (guidance 3.5, LoRA 1.0).
Look D (`--guidance 2.5 --lora 1.15`) is more muted with finer lines but drifts toward full body; use B unless asked.

## 8. Getting 2/3-body framing

1. Render `--count 4` and keep the seeds that crop at the thigh (about 50–60%).
2. Describe head-to-hip details (face, hat, coat, belt, held prop at chest or hip). **Don't mention footwear,
   floor-length robes or long capes**: they pull the model to full body.
3. Keep props close to the body (held at the chest, raised in a fist by the shoulder, hand on a hilt) so they stay in
   frame and the cut-out keeps them.
4. A full-body result isn't wasted: Broadside's importer cuts it at mid-thigh (`[seed, cut]` in portrait_picks.json).

## 9. 3D models and idle animations

- **`docs/3D_PIPELINE.md`**: image → **validated** reference → TRELLIS.2 model (GLB) → Blender preview.
- **`docs/IDLE_ANIMATION.md`**: portrait → seamless **looping** idle (Wan 2.2 first/last frame) with an automatic loop
  check.

**User rules:** validate every reference image before any image-to-3D step; every idle must loop.
