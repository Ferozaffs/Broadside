# Pirate Game – 2D Art Pipeline (handover)

You are picking up a working, tested local image-generation pipeline. Your job: generate 2D art assets for the
user's **pirate game**, starting with **character dialogue portraits**. Everything below was set up and verified on
2026-11-19. Read this file fully before generating anything.

## 1. Art direction

- **Asset type:** dialogue-screen character portraits, composed like `reference/composition_ref_dialogue_screen.webp`:
  the character stands at one side of the screen, a dialogue box sits beside them, and the screen edge cuts the body
  at about mid-thigh ("2/3 body").
- **Deliverable per character:** transparent-background PNG (`*_alpha.png`) plus the original on dark grey.
- **STYLE DECISION: use `amadmir` for all game assets.** This is the user's decision (2026-11-19). Always pass
  `--style amadmir` unless the user explicitly asks for something else.
  | Style key | Status | Look | Reference |
  |---|---|---|---|
  | `amadmir` | **CHOSEN – production style** | comic-book ink linework, fine hatching, muted desaturated colours, painted shading | `reference/style_ref_amadmir_civitai_28401179.jpg` |
  | `hades` | not used for the game; kept installed only for comparison | bold graphic cel shading, hard shadows, inked outlines (Hades-like) | `reference/style_ref_hades_pony_civitai_30810042.jpg` |
- **Consistency rule:** the STYLE + FRAMING text is fixed per style. Change only the CHARACTER text between
  characters, or the cast won't match. If the pirate theme needs a style tweak (e.g. `dark fantasy` → `pirate
  adventure`), agree it with the user once, update `tools/make_workflow.py`, regenerate, then freeze it.
- Don't use `hades` for game assets: its LoRA was trained on Supergiant's Hades art, which is a legal grey area for a
  shipped game.

## 5. How to generate

```
cd C:\Users\USER\Documents\PirateGame-ArtPipeline
python -I tools/generate.py --style amadmir --name captain_redbeard --count 4 --character "<sentences>"
python -I tools/generate.py --style amadmir --name captain_redbeard --seeds 424242 --character "<sentences>"
```
- Files go to `assets/characters/<name>/<name>_<style>_s<seed>.png` and `..._alpha.png`.
- Every run appends to `generation_log.jsonl` (time, style, character text, seed, files). That log is the shared record
  between you, the user and any other agent; **never rewrite it, only append**.
- Workflow: explore with `--count 4`, show the user, then lock the chosen seed and iterate on wording with `--seeds <seed>`.
- To review results, open the PNGs (the Read tool shows images). Check the alpha version for clipped thin weapons and
  hair.

### CHARACTER prompt guides
**hades (Pony):** booru tags. Start with `1boy`/`1girl`, `solo`, then hair, eyes, outfit pieces, held item, pose and
expression. Quality tags are already in the STYLE text. **Weight every key colour**, because colours bleed between
garments, hair and the background (a black robe once turned the hair black, and grey background bled into clothes):
`1boy, solo, pirate captain, (red beard:1.2), tricorn hat, (navy blue long coat:1.2), gold buttons, holding cutlass, smirk`

**amadmir (Flux):** one to three natural sentences starting with "The character is ...":
`The character is a weathered pirate captain with a braided red beard and a scar across his cheek, wearing a navy blue long coat with tarnished gold buttons and a black tricorn hat. He rests one hand on a cutlass at his hip and smirks.`

## 6. Test findings (4-character cast: mercenary, rogue, elderly witch, demon blacksmith; same seed per style)

- **hades:** style **very stable**. Line weight, shading and palette match across all characters, framing is
  consistent (head to just above the knee) and all cut-outs are clean. Weak points: stiff, front-facing poses; it
  sometimes **duplicates weapons** (greatsword drawn twice), so reroll the seed; materials can turn glossy (the
  leather apron looked like latex), so add a `matte leather`-style tag.
- **amadmir:** style **very stable** and prompt adherence is better than Pony (witch had lantern **and** stick,
  demon got a tail). Detail is higher. **Framing problem:** at 832×1216 it drew **full body (head to feet)** for all
  four characters, even with explicit "cropped at mid-thigh, feet out of frame" wording (see
  `reference/test_cast_amadmir_v1_fullbody.jpg`, `_v2_fullbody.jpg`). The first single test (a blonde warrior) did
  frame at the thigh. Likely cause: the LoRA's full-body concept-art bias plus the tall canvas.
  **Fix applied:** canvas changed to **896×1152**. Now about 3 of 5 come out correctly framed: rogue (hip/thigh),
  demon (knee) and the pirate captain test (thigh, `assets/characters/test_pirate_captain/`). Mercenary and witch
  were still full body (`reference/test_cast_amadmir_v3_896x1152.jpg`). See §8 for how to handle this.
- BiRefNet cut-outs are usually clean (thin staves, loose hair strands kept). **But it can delete props held away
  from the body:** the witch's glowing lantern vanished from the alpha PNG. Always compare `_alpha.png` with the
  original before accepting an asset.
- Weapons and props named in the prompt sometimes change form (a sword became a claw-like blade). Reroll or describe
  them more concretely.

## 8. Getting 2/3-body framing with amadmir (current best practice)
1. Render `--count 4` per character and keep the seeds that crop at the thigh. Framing varies by seed, so expect
   about 50–60% to come out right.
2. Describe head-to-hip details (face, hat, coat, belt, held weapon at chest or hip level). **Don't mention footwear,
   floor-length robes or long capes**; those pulled the model to full body in testing.
3. Keep props close to the body (held at the chest, resting on the shoulder, hand on hilt) so they stay in frame
   and BiRefNet keeps them.
4. A full-body result isn't wasted: the game can place it so the screen edge cuts at mid-thigh (as in the composition
   reference). But the thigh-up part is then only about 700 px tall, so it needs an upscale step. That isn't set up:
   it needs an upscale model download (put it on K:) and the user's OK first.
5. Ideas not yet tested: Amadmir LoRA strength 0.8–0.9 (may weaken the full-body bias but also the style); a
   1024×1024 canvas.
